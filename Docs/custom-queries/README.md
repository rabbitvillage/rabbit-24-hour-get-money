# 客製化查詢指令（custom queries）

這裡放可以重複跑的分析腳本。全部**唯讀**：只讀 `btc5m_sim/data*/` 的 CSV 和 Polymarket 公開的 data-api『公開資料介面』，不碰 `.env`、不下單、不改主機。標準函式庫就能跑，不用裝套件。

資料在主機上，所以通常是把這個資料夾 `scp` 到主機 `/tmp/cq/` 再跑：

```bash
scp -P 22888 Docs/custom-queries/*.py root@100.75.171.83:/tmp/cq/
```

需要錢包地址的腳本，用機器人自己的 identity『身分查詢』拿代理錢包地址（公開地址，不含金鑰）：

```bash
cd /opt/rabbit-24-hour-get-money && set -a; . btc5m_sim/.env; . btc5m_sim/.live.env; set +a
W=$(python3 -c 'import btc5m_sim.live as L; print(L.identity()["proxyWallet"])' | tail -1)
```

data-api 每分鐘抓太多會回 429『請求太多』，腳本已經每頁停 1.5 秒並自動重試；同一分鐘內不要連跑兩支抓鏈上的腳本。

共用模組：`polyaudit_lib.py`（抓 activity、讀機器人帳本、把鏈上成交配對到機器人訂單）。配對規則是 slug＋方向＋時間 ±300 秒＋股數相符；只用 slug＋方向配會把手操買同一邊的單算成機器人的。

## audit_chain.py：手續費與手操稽核

- **用途**：對帳。算機器人每筆真單在鏈上實際付的手續費（帳本記 0），以及不屬於機器人的加密盤手操按日、按買價的損益。
- **參數**：`<代理錢包地址> <repo 根目錄> [最多抓幾列，預設 6000]`
- **怎麼跑**：`python3 -I /tmp/cq/audit_chain.py "$W" /opt/rabbit-24-hour-get-money`
- **怎麼看**：`fee paid on those fills` 是真單總手續費；`ledger pnl ... -> after fees` 才是真正損益。手操表的 P&L = 賣出 + 結算領回 − 買進（手續費已含在買進金額裡）。`not found on chain` 是帳本有、鏈上沒抓到的單（通常是超出抓取範圍）。
- **不能拿去下單的情況**：這是事後對帳，不是訊號。手操的輸贏是當天的結果，不代表方法有優勢；樣本少於幾百筆時 ±10% 都是雜訊。

## manual_day.py：某一天的手操逐場檢視

- **用途**：把某一天（台灣時間）的手操一場一場列出來，旁邊放機器人自己錄到的行情：收盤時離開盤價幾 bps、最後 150 秒領先方換邊幾次、剩 120 秒時的領先方最後有沒有贏。可用 `split` 把一天切成前後兩段比較「做得上去」和「崩掉」的時段行情有沒有差。
- **參數**：`<代理錢包地址> <repo 根目錄> <YYYY-MM-DD> [切分時間 HH:MM] [幣 btc/eth/sol，預設 btc]`
- **怎麼跑**：`python3 -I /tmp/cq/manual_day.py "$W" /opt/rabbit-24-hour-get-money 2026-10-24 19:05 btc`
- **怎麼看**：`fav/dog` = 第一筆買的是領先方還是落後方；`held` = 有部位抱到結算；`both` = 同一場兩邊都買過；`entry_s` = 第一筆買進距離收盤幾秒；`flips` = 最後 150 秒領先方換邊次數；`lead120` = 剩 120 秒的領先方最後贏了沒；`move_bps` = 收盤價離開盤價幾 bps。下方 `[before/after]` 是兩段的手操統計和「該時段所有場次」的行情統計。
- **不能拿去下單的情況**：一天幾十場分不出技術和運氣（每場 $20 的賭注，36 場的隨機波動一個標準差約 ±$85）。行情統計是事後看的，收盤前不知道。

## flip98.py：0.98～0.99 進場後翻船率

- **用途**：假設最後 N 秒內領先方賣價一到 0.98～0.99 就買，統計翻船率（買的那邊輸）和每股損益（未扣手續費），分美股時段／非美股時段。
- **參數**：一個或多個資料夾 `btc5m_sim/data btc5m_sim/data-eth btc5m_sim/data-sol`
- **怎麼跑**：`cd /opt/rabbit-24-hour-get-money/btc5m_sim && python3 -I /tmp/cq/flip98.py data data-eth data-sol`
- **怎麼看**：買 0.98 要賺錢，翻船率要低於約 1.86%（扣手續費後）；買 0.99 要低於 0.93%。表下方列出每一次翻船的場次。
- **不能拿去下單的情況**：它假設看到賣價就買得到；真單約 16% 會貴 1 分，而且有逆向選擇（能成交的常是快翻的）。翻船樣本只有個位數時，±1% 都是誤差。

## tail98.py：專吃 0.97／0.98 的期望值

- **用途**：假設只在最後 60／45／30 秒、領先方賣價剛好 0.97 或 0.98、掛單夠深時買，算每天機會次數、翻船率、扣手續費後每股期望值，以及貴 1 分成交時的期望值。
- **參數**：同 flip98.py
- **怎麼跑**：`python3 -I /tmp/cq/tail98.py data data-eth data-sol`
- **怎麼看**：`ev/share` 是扣手續費（7%×p×(1−p)）後每股期望值（分）；`worse1c` 是成交貴 1 分時的期望值。正的才有肉。`n/day` 是頻率。
- **不能拿去下單的情況**：2026-10-26 跑的結果，BTC 0.97 最後 45 秒每股約 +1 分，但翻船只有 6 次樣本（95% 區間跨過損益兩平），要再累積至少一個月資料重跑才能決定。

## real_orders_by_ask.py：真單按看到的賣價分組

- **用途**：機器人真單（已成交已結算）按決定時看到的賣價分組：筆數、勝率、帳本損益、成本、報酬率、成交價和賣價的平均差。
- **參數**：資料夾，例如 `data data-sol data-eth`
- **怎麼跑**：`python3 -I /tmp/cq/real_orders_by_ask.py data data-sol data-eth`
- **怎麼看**：`ret` 是帳本報酬率，**沒扣手續費**（0.98 約 0.14%、0.90 約 0.63%，用 audit_chain.py 的數字扣）。`avg(fill-ask)` 負數表示平均成交比看到的便宜，但會被翻盤後成交的極端值拉低，看分布請用 fill_slip_hist.py。
- **不能拿去下單的情況**：每個價位幾十筆，一筆輸單就改變結論。

## loss_streaks.py：真單連輸的日子，現在的設定還會不會發生

- **用途**：把所有真單（live_orders 成交 × live_results 結算）按時間排，找出連輸 ≥N 筆的段落；對每一筆輸單用「現在的」設定重放：ETH 已停、美股時段停單、0.80～0.95 價位帶與 60 秒窗口、方向＋距離過濾、震盪過濾、輸單冷卻、每場一筆、事件行事曆，列出哪些會擋、哪些「現在也會進場」。重放是循序的：只有現在會進場的輸單才會啟動冷卻、佔掉同場名額。
- **參數**：`[連輸門檻，預設 3]`；參數從環境讀（先 `set -a; . btc5m_sim/.env; set +a`，SOL 距離倍率用 `DIST_SCALE_SOL=0.004`）。
- **怎麼跑**：`cd /opt/rabbit-24-hour-get-money && python3 Docs/custom-queries/loss_streaks.py 3`
- **怎麼看**：每段連輸列出每筆的規則、賣價、成交價、剩秒、距離、振幅、損益，`|` 後面是現在會擋的原因；`★ 現在也會進場` 就是現在的設定擋不住的那種輸單。最後有全部輸單的統計。2026-10-27 跑：35 筆輸單中 33 筆現在會被擋，2 筆（10-26 10:59、13:49，BTC w60 非美股時段的尾盤翻船）現在也會進場。
- **不能拿去下單的情況**：這是用歷史資料重放今天的規則，資料有缺（10-20 前 BTC 沒距離紀錄）時會寫「沒有距離資料」；它證明的是「過去那種連輸的原因已經不在」，不是「以後不會輸」。

## ws_vs_rest.py：websocket 盤口和 REST 一不一樣

- **用途**：自己開一條 BookFeed『盤口即時推送』，在每場最後 90 秒每秒拿 REST /book 來比：兩邊最佳賣價、ws 盤口幾秒沒更新、層數、0.97 以下的深度。看「找不到對手單」是不是盤口舊（phantom『ws 有、REST 沒有』）或成交比看到的便宜很多（missing『REST 有更便宜的、ws 不知道』）。不碰機器人。
- **參數**：`<幣> <觀察幾場>`
- **怎麼跑**：`cd /opt/rabbit-24-hour-get-money && nohup python3 Docs/custom-queries/ws_vs_rest.py btc 3 > /tmp/ws_vs_rest.log 2>&1 &`，看 `grep SUMMARY /tmp/ws_vs_rest.log`
- **怎麼看**：`fav_same / fav_cmp` 是領先方（0.5～0.99）最佳賣價相同的比例；`fav_phantom`、`fav_missing` 要接近 0。2026-10-27 12:03 跑 BTC：第一場 37/37 相同、0 phantom、0 missing。
- **不能拿去下單的情況**：這是資料品質檢查，不是訊號。

## fill_slip_hist.py：成交價比看到的賣價差幾分

- **用途**：真單成交價減決定時賣價的分布（分），和看盤口到交易所回覆的平均延遲。
- **參數**：資料夾
- **怎麼跑**：`python3 -I /tmp/cq/fill_slip_hist.py data data-sol data-eth`
- **怎麼看**：`0` 原價成交，`1` 貴 1 分，負數比看到的便宜。2026-10-26：125 筆，56% 原價、18% 貴 1 分、8% 貴 2 分、18% 便宜；0.97～0.99 的單 16% 貴 1 分。
- **不能拿去下單的情況**：這是成本估計，不是訊號。

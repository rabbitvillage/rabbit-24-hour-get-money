# FR-20261029-recheck-direction：送單前再檢查改成有方向性——跌 0.02 就不買、漲一格就追一格

- 狀態：active（fish 10-29 15:0x：「立刻加入，這不是策略是避險」；本機 122 個測試通過、主機 Python 3.12 也全過；待部署）
- 來源：FR-20261027-recheck-before-send 的延伸；10-29 14:09 主帳／acct2 同場分歧的案例

## 1. 改了什麼
`btc5m_sim/live.py` 的送單前再檢查（簽名前、POST 前各看一次 ws 盤口）：
1. **跌**：`LIVE_RECHECK_DROP` 預設 0.05 → **0.02**。領先方賣價比決定時低 ≥0.02 就不送（原本要 ≥0.05）。
2. **漲**：新增 `LIVE_RECHECK_CHASE`（預設 0.02）和 `LIVE_CHASE_MAX`（預設 0.95）。賣價漲到超過限價、但超過的幅度 ≤0.02 而且仍 ≤0.95 時，不再取消，改用「新賣價 + SLIP」重新定價：簽名前發生就直接改價再簽；簽名後才發生就用新的冪等鍵再簽一次（最多一次），再看一次盤口後送出。再漲就放棄（`rose again`）。帳本 `msg` 記 `chased 0.90 -> 0.93 before/after sign, limit 0.95`，journal 有 `live chase` 行。
3. 啟動行多印 `recheck drop 0.02 chase 0.02 (<= 0.95)`。

## 2. 為什麼
簽名那 0.4～1 秒內價格往哪邊動本身就是訊號（661 筆真單，成交價 − 決定時賣價）：漲 1～2 分 203 筆輸 3%（+$40）；沒動 282 筆輸 1.4%（+$52.8）；**跌 0.01～0.05 共 122 筆輸 10%（−$14.9，淨虧）**；跌 ≥0.05 輸 26%（已擋）。另外「漲過限價而取消」的 16 筆裡 15 筆事後贏（10-29 14:09 那筆是唯一的例外）。所以跌的門檻收緊、漲的改追。

## 3. 修改前
跌 <0.05 照送；漲過限價一律取消。

## 4. 修改後
跌 ≥0.02 不送；漲 ≤0.02（且 ≤0.95）追一格，成交價最多貴 2 分；漲更多或超過 0.95 仍取消。

## 5. 影響的檔案
`btc5m_sim/live.py`（`RECHECK_DROP`、`RECHECK_CHASE`、`CHASE_MAX`、`_book_moved` 回傳 chase、`_submit` 兩段改價邏輯、成交訊息保留 chase 註記）、`tests/test_btc5m_live.py`（跌 0.02 的案例、追價 ×6 情境）、`btc5m_sim/.env.example`。

## 6. 對交易、下單、風控、資料判斷的影響（執行層，規則不變）
- 會少送一些「正在跌」的單（歷史約 18% 的成交屬於跌 0.01～0.05，輸率 10%），預期少輸、淨利略增。
- 會多送一些「正在漲」的單（歷史 16 筆取消中 15 筆贏），每筆成交價最多貴 2 分；追價後的金額仍受 Worker 單筆 $60 限制（60 股 × 0.97 = $58.2 OK）。
- 追價後再簽一次多花約 0.4 秒，只在簽名後才漲的情況發生。
- acct2 共用同一份程式，重啟後同樣生效（它每筆 5 股）。

## 7. 驗證
部署後啟動行有 `recheck drop 0.02 chase 0.02`；之後看 journal 的 `live chase`／`live aborted ... side collapsing` 行和 `live_orders.csv` 的 `msg`。一週後統計：追價成交的輸率（預期 ≤5%）、跌 0.02～0.05 被擋的場次事後結果。

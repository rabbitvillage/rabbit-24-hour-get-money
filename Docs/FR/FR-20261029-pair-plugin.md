# FR-20261029-pair-plugin：開盤配對助手（Chrome 插件，人工下單＋紀律鎖）

- 狀態：active（本機 4 個規則測試通過；在真實頁面未登入狀態測過切邊、讀選中邊、1-Tap 按鈕偵測、盤口串流與成交介面連線；待 fish 登入後實測市價模式）
- 來源：fish 10-29：「把它插件化，人類盯盤、人類決策，但要嚴守紀律，不可以放大股數」「最大的問題是切換 Down 跟 Up 的滑鼠移動」；選 Chrome、每張 $5。

## 1. 改了什麼
新增 `pair_plugin/`（Chrome MV3 插件）：`logic.js`（規則純函式：手續費、第二張上限、部位、該做什麼、結算損益）、`content.js`（面板、盤口 websocket、讀自己的成交、擋違規、一鍵買）、`panel.css`、`options.html/js`（錢包地址、每張金額、觸發價）、`README.md`（安裝與用法）。測試 `tests/test_pair_plugin.js`（`node --test`）。

## 2. 為什麼
API 下單受簽名延遲與簽名服務限制（0.50 以下拒簽），新 VPS 還沒到；網頁手動下單可以立刻用真錢小額驗證規則，但人會手癢放大、會切錯邊、滑鼠移動慢。插件把規則變成提示和硬性限制，並把切邊＋填金額＋按買入縮成一個鍵。

## 3. 修改前／4. 修改後
修改前：fish 手動看盤手動按，沒有紀律限制、沒有紀錄。修改後：面板即時顯示兩邊賣價與規則狀態；空白鍵買規則指定的那一邊；不符合規則或金額超過上限的「買入」與 1-Tap 點擊會被攔下；每場結算後自動記損益與是否成對。

## 5. 影響的檔案
`pair_plugin/*`、`tests/test_pair_plugin.js`、本檔。不碰主機、不碰機器人。

## 6. 對交易、下單、風控、資料判斷的影響
插件不會自己下單：每一筆都要 fish 按鍵或點擊。限制：第一張只在開盤 0～60 秒、只買賣價 ≤ 觸發價的那邊、金額 ≤ 設定值（預設 $5）；第二張只買另一邊、價格 ≤ 上限、金額 ≤ 同股數所需 ×1.03；同場成對後全部擋下；送出後 5 秒內擋下重複按。不讀私鑰、只讀公開成交紀錄。

## 7. 驗證
fish 登入後第一筆用 $1～$5 實測：空白鍵能切邊、填金額、送出；成交後面板部位在 5 秒內更新；違規點擊會被擋。之後用面板的今日統計和主機回放（`pair_first040.py`）對照。

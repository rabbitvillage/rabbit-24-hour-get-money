# FR-20261030-pair-plugin-manual：開盤配對插件改成人工模式（第二張掛限價單）

- 狀態：active（未登入狀態已測；登入後實際下單未測）
- 日期：2026-10-30

1. **改了什麼**：`pair_plugin/` 從「固定規則（第一分鐘 0.40 觸發）」改成人工模式：
   - 第一張由人決定時機和邊。空白鍵買較便宜的一邊，U／D 鍵指定邊，只能用市價，金額固定。
   - 第二張由空白鍵自動切到限價、填同樣股數、價格 = 1 − p1 − 第一張手續費 − 目標利潤（預設 0.07，可在設定頁改）。
   - 檢查也涵蓋限價單：第一張不准用限價；第二張價格不能高於上限、股數不能超過第一張；第二張掛出後擋下重複掛單，面板提供「重掛」。
   - 每場記錄第一張按下當下的兩邊賣價、前 60 秒走勢、成交、第二張掛單、結算，設定頁可下載 CSV。
   - 結算損益：第二張若是掛單不算手續費。
2. **為什麼**：
   - fish 的進場判斷（震盪大、一邊壓到很低）寫成固定規則都不賺錢（`pair_unfilled_check.py`），要先記錄 fish 實際怎麼判斷。
   - 官方文件和頁面都確認掛單不收手續費；第二張用掛單，每對多 1.5～2 分。
   - 回放顯示目標利潤 7～10 分比 3 分好（`pair_first_minute_30.py`）。
3. **修改前**：只有開盤 60 秒內、賣價 ≤ 0.40 那一邊能買第一張；第二張用市價、上限是扣兩次手續費後打平的價格；沒有每場紀錄。
4. **修改後**：見第 1 點。插件依然只在人按鍵或點按鈕時才下單。
5. **影響檔案**：`pair_plugin/logic.js`、`content.js`、`options.html`、`options.js`、`panel.css`、`manifest.json`（0.2.0）、`README.md`；`tests/test_pair_plugin.js`（5 個測試）。
6. **對交易、下單、風控、資料判斷的影響**：
   - 會下真實單：人按空白鍵時插件會點頁面的送出按鈕。第一張金額上限和「同樣股數」限制都還在。
   - 新風險：限價單掛出後若沒成交會一直掛到收盤；要重掛得先手動取消舊單。
   - 不影響主機上的記錄器 `pm-pair-recorder`。
7. **驗證**：
   - node 測試 5／5 通過。
   - 2026-10-30 在未登入頁面實測：切換 1-Tap／市價／限價、選邊、填 61¢ × 16.66 股，頁面總計顯示 $10.16（正確）；讀到的送出內容正確。
   - 頁面顯示不跨價的限價單「贏取」等於股數（不收手續費）。
   - 公開持倉股數等於成交紀錄股數，手續費是另外扣現金，不是扣股數。
   - **剩下要驗收**：登入後用 $5 實際跑一場。

- **修改前**：紀錄沒有幣價資訊。
- **修改後**：見上。

## 補充 2026-10-30：練習模式（v0.3.0）

- **改了什麼**：
  - 新增練習模式，預設開啟，面板最上面勾選切換；切到真實模式要按「確定」。
  - 練習模式下，空白鍵／U／D 不碰頁面上的下單按鈕，改用當下真實盤口模擬成交：
    - 第一張照賣單往上吃到設定金額（`fillMarket`『照盤口算花多少錢買到幾股』），手續費照官方公式另扣。
    - 第二張掛單：對面賣價 ≤ 掛單價就算成交（和回放同算法），不收手續費；另記 `leg2_fill_strict`『跌破掛單價 1 分才算的嚴格成交』。
    - 掛單時若已低於對面賣價，立刻用 `fillShares`『照盤口買指定股數』吃單成交，收手續費。
  - 練習模式擋下頁面上所有真的買入按鈕。
  - 練習的成交、結算、統計和真實的分開存（`sim`『練習成交』、`settledSim`『練習結算』）；紀錄多 `mode`『sim 練習／live 真實』、`leg2_taker`『第二張是否吃單』欄。
  - 離開頁面的練習場次，收盤後由每 30 秒的補資料程序自動結算。
- **為什麼**：fish 要「不用花錢也能跑」，先累積他的按鍵時機和模擬成績，再決定要不要真的下單。
- **修改前**：空白鍵一定會真的下單。
- **修改後**：預設不花錢；要真的下單得自己關掉練習模式並確認。
- **影響檔案**：`pair_plugin/logic.js`（`fillMarket`、`fillShares`、紀錄欄位）、`content.js`、`panel.css`、`options.html`、`manifest.json`（0.3.0）、`README.md`；`tests/test_pair_plugin.js`（7 個測試）。
- **對交易、下單、風控、資料判斷的影響**：預設改成不下單，真實下單路徑與擋單規則不變。練習成績偏樂觀：掛單成交用「對面賣價碰到」近似，沒算排隊，可參考嚴格成交欄。
- **驗證**：
  - node 測試 7／7 通過。
  - 在模擬網頁環境（jsdom『模擬網頁環境的工具』，腳本在工作階段暫存區，沒放進專案）跑完整流程 16 項全部通過：
    - 兩條串流連線、預設練習、面板提示、離線距離顯示。
    - 第一張照盤口吃成 13 股；第二張掛 0.52；對面 0.53 不成交、0.52 成交。
    - 擋真實按鈕、取消確認後維持練習。
    - 收盤後結算 +$1.025（掛單不收手續費）、改用官方開盤價、練習不寫進真實統計。
  - 還沒在真的 Chrome 擴充功能裡跑過。

## 補充 2026-10-30：第二張改成由人決定時機＋第三格即時利潤（v0.4.0）

## 補充 2026-10-30：面板顯示版本、舊程式自動停用（v0.5.1）

- **問題**：fish 重新載入插件後仍看到舊版行為。btc-updown-5m-1793335500 的第二張仍是 v0.3 的目標價掛單（0.57）。
- **原因**：Chrome 系瀏覽器重新載入插件後，已開著的分頁不會換新程式；Polymarket 換場是頁內切換、不會重新載入頁面，所以舊程式一直跟著。
- **改了什麼**：
  - 面板標題顯示版本號（`chrome.runtime.getManifest()`『讀插件版本』）。
  - 舊程式偵測到自己已失效（`chrome.runtime.id`『插件編號』消失）時，停止攔空白鍵、Enter、下單按鈕，面板變紅提示「請按 Cmd+R 重新整理這一頁」。
  - README『說明文件』補上更新步驟。
- **影響檔案**：`pair_plugin/content.js`、`manifest.json`（0.5.1）、`README.md`。
- **對交易、下單、風控、資料判斷的影響**：無。舊程式停用後頁面回到 Polymarket 原本的行為；在真實模式下，舊版的擋單也會跟著停止，要重新整理頁面才有新版保護。
- **驗證**：模擬網頁環境 12 項通過，包含版本顯示、舊程式停用並提示、舊程式不再攔空白鍵。
- **限制**：這次 fish 分頁裡跑的 v0.3 沒有這段程式，這一次仍要手動按 Cmd+R。

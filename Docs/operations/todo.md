fish 10-27 的題目：有沒有辦法「增加安全、不損失利益」。下面每一項都標了對安全和對利益的影響，依據是這幾天的資料（Docs/custom-queries/ 可重跑）。

現狀的風險輪廓：每筆錢包 1/15（約 $7.4），翻船率 2～5%，大約每 20～50 筆輸一次；一次輸等於 10～25 筆的利潤。真正沒被控制住的，不是單筆大小，而是下面 A 組的四件事。

## A. 不損失利益、純增加安全（優先）

1. **手續費入帳、排除 dry 列**
   - 做什麼：`live.py` settle() 把 `fee = 0.0` 改成 7%×p×(1−p)×股數；`review.py`、`push_dashboard.py` 加總時只算 `live_orders.csv` 有 filled 的鍵（`live_results.csv` 混有 dry 列、沒有 status 欄）。

   - 安全：加碼決定不會建立在高估的損益上。利益：0。成本：小。臨時做法：`Docs/custom-queries/audit_chain.py`。
   - 10-27 進度：`fee` 欄已從 10-27 13:2x 起記真實手續費（FR-20261027-exec-details），review 摘要顯示淨值；`pnl` 仍是毛利（停損不變）。剩下：11-02 後決定 pnl 是否改淨值、看板是否顯示淨值。

2. **只在異常時通知**

   - 為什麼：10-26 18:07 自我檢討誤放 STOP，通知全關所以沒人知道。
   - 安全：靜默停機最多幾小時內被發現。利益：0。驗收期內照 fish 規定全關，11-02 後開。

3. **盤口來源健康檢查（no-match 升到 50%）**
   - 做什麼：BTC 送單「找不到對手單」10-21 是 0%、10-23～24 是 20%、10-27 是 5/10。先累積兩天；用 `python -m btc5m_sim.feeds` 比 websocket 和 REST 的差；若 ws 的書太舊，加「超過 N 秒沒更新就退回 REST」的門檻。
   - 安全：避免拿舊盤口下單（舊盤口不只會沒成交，也可能成交在已經變壞的價位）。利益：成交率回升，反而增加。成本：中。

## B. 可能同時增加安全和利益

6. **縮短送單延遲（現在 1.3 秒）**
   - 數字：看盤口→交易所回覆 1,301 ms = 組單 200 + 簽名 732（Cloudflare Worker）+ 送單 363。16% 的尾盤成交貴 1 分，no-match 的一部分也來自這 1.3 秒。
   - 做法候選：決定前 30 秒對兩邊各預簽幾個價位（0.85～0.97、固定股數）的單，決定時直接送對應那張（省 0.7 秒）；或 Worker 保持連線／換近一點的區域。
   - 安全：成交更接近決定時看到的盤口。利益：貴 1 分和沒吃到都會減少。成本：中，要先在 dry 模式測。

7. **XRP 只開影子**
   - signer 白名單已含 xrp，`add_asset.sh xrp` 可裝；裝好先放 STOP 檔，只讓 sim 記錄，IO 監測加 `data-xrp`。
   - 安全：零風險。利益：一週後知道值不值得加第四個幣。

## B2. 主機遷移（fish 10-27：最後一步會搬到倫敦）— 先看這兩件事

- **英國在 Polymarket 的封鎖名單上**（官方 geoblock 文件：United Kingdom = close-only，前端和 API 都不能開新倉）。搬到倫敦後下單還是得走非封鎖地區的代理出口，和現在一樣；倫敦 IP 本身不能直接下單。遷移前一定要從新主機的出口 IP 跑 `curl https://polymarket.com/api/geoblock`，`blocked` 必須是 false。
- **倫敦對延遲沒有好處**：交易所的 API 在美東（主機在紐約時直連 GET /time 190 ms、經 Sofia 代理暖連線 170 ms，差距很小；POST /order 的 350 ms 主要是交易所撮合時間）。倫敦到美東單程約 40 ms，盤口 ws 和送單都會各多 40～80 ms。要搬的理由只能是營運／法律，不是效能。
- 若要兼顧：主機留美東（靠近交易所、盤口最快），代理出口選名單外、離美東近的地方（文件沒列：墨西哥、巴拿馬、哥倫比亞、百慕達、巴哈馬、加拿大 BC/ON/AB/QC 以外的省；保加利亞也不在名單）。名單會變，每次換出口都要重跑 geoblock 檢查。
